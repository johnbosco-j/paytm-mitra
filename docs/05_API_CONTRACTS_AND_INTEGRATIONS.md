# 05 — API contracts, adapters, and integration policies

## 1. API style and baseline

FastAPI exposes `/api/v1/*` with generated OpenAPI. Web uses an autogenerated typed API client; no handwritten endpoint URL duplication. Use JWT auth, verified `store_id` access per request, cursor pagination, standard errors, tracing and idempotency for mutations. API return fields include `data`, `meta` where appropriate and normalized error shape.

### Error envelope

```json
{"error":{"code":"NO_COST_BASIS","message":"Unit purchase cost is needed before calculating margin.","details":{"product_id":"uuid"},"correlation_id":"uuid"}}
```

Do not place secret fields or other-store metadata into `details`.

## 6. Adapter contract (all outside providers)

Each integration implements an internal interface with methods such as `test_connection()`, `fetch_page(cursor)`, `normalize(raw)`, `verify_webhook(headers,body)`, `capabilities()`, and `disconnect()`. No domain service should depend on a single provider's payload.

### Adapter error taxonomy
- `NotConfigured`, `PermissionDenied`, `RateLimited(retry_after)`, `TransientProviderFailure`, `SchemaChanged`, `UnsupportedCapability`, `InvalidSignature`.
- All errors return sanitized merchant explanations, log a correlation ID, and avoid retries for permanent failures.

### Paytm adapter scope

**Verified context:** Paytm provides developer-facing payment and settlement interfaces for qualifying merchant integrations; specific accessibility depends on Paytm business product, credentials and terms. These are not proof of access to *every* merchant transaction, SKU-level detail, customer phone or settlement record.

**Implementation order:**
1. Authorized CSV statement upload (generic secure importer) + schema mapping.
2. Merchant-authorized account connection if an officially supported OAuth/API process is actually available.
3. Approved settlement/transaction/status adapter with sandbox credentials and signature verification, only after legal/technical eligibility.
4. Enable production sync behind tenant-scoped flag after privacy review; replay and drift tests.

**Prohibited shortcuts:** do not scrape merchant dashboards, use shared credentials, claim a Paytm partnership, or invent endpoint names, signing algorithms, test keys, subscription entitlements, or webhook event types. Discover them from the **current official Paytm documentation and granted merchant product**.

### Voice provider adapter
- `transcribe_audio` returns language, transcript, timestamps if provider offers them, confidence when actually supplied, usage/cost metadata and raw provider request ID.
- Sarvam supports Tamil `ta-IN` in documented models; verify current model and SDK names before implementing.
- If confidence not provided by provider, mark `confidence_source=heuristic|unknown` rather than inventing precise confidence.
- Minimize voice retention, encrypt source storage, require consent where appropriate.

### Model adapter
- `extract_request`, `explain_opportunity`, `summarize_trial`, `draft_campaign`, `suggest_supplier_comparison`, no direct `execute_payment`.
- Strong typed Pydantic input/output, explicit timeouts, token budget, price budget, provider fallback and quality evals.

### Notification adapter
- `send_message` only from a validated approval + recipient consent context; avoid spamming and respect opted-out recipients.
- Email via Resend or approved provider can be used for invited staff/merchant alerts; outbound marketing has separate constraints.

## 7. Realistic CSV import contract

Importer must support common variations for date, INR symbol, debit/credit, amounts with commas, timezone and transaction IDs. Preview includes headers/mapping, 10 sample rows, rejected rows and reason counts, no full-row financial data transmitted to the LLM. Save original source file checksum and mapping version. Normalized rows are duplicate-safe and reversible via import batch rollback procedure.

## 8. Versioning and generated client

- FastAPI OpenAPI is authoritative; generate typed TypeScript client in `packages/contracts` during CI.
- Reject breaking response changes without contract version bump / consumer tests.
- An API error must have stable machine-readable `code`, localized user-readable copy in UI.
- All mutating requests include expected entity revision or idempotency key where concurrency matters.

## 9. Security checklist per endpoint

**Every endpoint:** login? active membership? role? store scope? input size? rate limit? idempotency? audit event? error secrecy? no raw secrets? required merchant approval? tests for forbidden cross-tenant ID?
